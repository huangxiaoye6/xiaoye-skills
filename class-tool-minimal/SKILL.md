# Class Tool Minimal

## 目标

在实现“工具封装”任务时，强制遵循：
- 仅使用类进行封装
- 每个函数都必须是工具所需的公开能力
- 禁止生成辅助函数（含私有 helper、utils、wrapper）
- 禁止冗余代码
- 优先更低时间复杂度与空间复杂度

## 执行规则

1. **结构约束**
   - 只创建一个或多个职责清晰的类。
   - 函数必须直接服务于工具能力，不写“仅为复用而存在”的函数。
   - 不创建与需求无关的方法、字段、抽象层。

2. **函数约束**
   - 方法命名应直接表达工具动作（如 `parse`、`transform`、`validate`）。
   - 仅保留必要的输入参数和返回值，避免“预留参数”。
   - 若某逻辑只调用一次，优先内联到目标方法，而不是拆 helper。

3. **复杂度约束**
   - 默认选择线性或更优方案；避免不必要的嵌套循环。
   - 避免无意义拷贝与临时容器，尽量原地处理或流式处理。
   - 明确说明关键方法复杂度（时间/空间）并解释选择原因。

4. **代码质量约束**
   - 不写样板冗余（重复分支、重复转换、重复校验）。
   - 注释只保留关键设计决策，不写显而易见注释。
   - 异常处理仅覆盖真实失败路径，不做过度防御。

## 输出格式

在交付代码时使用以下顺序：

1. **类设计**
   - 类名与职责
   - 对外方法列表（仅工具必需）

2. **复杂度说明**
   - 每个关键方法的时间复杂度
   - 每个关键方法的空间复杂度
   - 为何这是当前约束下的更优方案

3. **实现代码**
   - 仅展示最终类实现
   - 不包含辅助函数与冗余演示代码

## 自检清单

- [ ] 是否全部通过类实现（无独立 helper 函数）
- [ ] 每个方法是否都直接对应工具需求
- [ ] 是否存在可删除的冗余分支/变量/中间结构
- [ ] 是否给出关键方法时间与空间复杂度
- [ ] 是否可在不新增辅助函数前提下保持可读性
